# Adaptive MAS-RCA PostgreSQL Database Schema

## 1. Overview

The Adaptive MAS-RCA system uses PostgreSQL to store incidents,
agent analysis results, user feedback, and confidence scores.

The database is designed using normalized relational tables with
primary-key and foreign-key relationships.

## 2. Tables

### 2.1 users

Stores users who submit incidents and provide feedback.

| Column | Type | Constraints | Description |
|---|---|---|---|
| user_id | UUID | PRIMARY KEY | Unique user identifier |
| username | VARCHAR(100) | NOT NULL | User name |
| email | VARCHAR(255) | UNIQUE, NOT NULL | User email |
| role | VARCHAR(50) | NOT NULL | User role |
| created_at | TIMESTAMP | NOT NULL | Account creation time |

### 2.2 incidents

Stores incidents submitted to the RCA system.

| Column | Type | Constraints | Description |
|---|---|---|---|
| incident_id | UUID | PRIMARY KEY | Unique incident identifier |
| user_id | UUID | FOREIGN KEY, NOT NULL | User who submitted incident |
| title | VARCHAR(255) | NOT NULL | Incident title |
| description | TEXT | NOT NULL | Incident description |
| severity | VARCHAR(20) | NOT NULL | Incident severity |
| status | VARCHAR(30) | NOT NULL | Current incident status |
| source | VARCHAR(100) | | Incident source |
| created_at | TIMESTAMP | NOT NULL | Incident creation time |
| updated_at | TIMESTAMP | | Last update time |

Foreign key:

`incidents.user_id → users.user_id`

### 2.3 agent_outputs

Stores outputs generated by the multi-agent RCA system.

| Column | Type | Constraints | Description |
|---|---|---|---|
| output_id | UUID | PRIMARY KEY | Unique agent output |
| incident_id | UUID | FOREIGN KEY, NOT NULL | Related incident |
| agent_name | VARCHAR(100) | NOT NULL | Agent that generated output |
| agent_type | VARCHAR(100) | | Type of RCA agent |
| diagnosis | TEXT | | Root-cause diagnosis |
| recommendation | TEXT | | Recommended action |
| reasoning | TEXT | | Agent reasoning/explanation |
| created_at | TIMESTAMP | NOT NULL | Output creation time |

Foreign key:

`agent_outputs.incident_id → incidents.incident_id`

### 2.4 confidence_scores

Stores confidence values associated with agent analysis.

| Column | Type | Constraints | Description |
|---|---|---|---|
| confidence_id | UUID | PRIMARY KEY | Unique confidence record |
| output_id | UUID | FOREIGN KEY, NOT NULL | Related agent output |
| score | DECIMAL(5,4) | NOT NULL | Confidence score |
| confidence_level | VARCHAR(30) | | High/Medium/Low |
| explanation | TEXT | | Explanation of confidence |
| created_at | TIMESTAMP | NOT NULL | Score creation time |

Foreign key:

`confidence_scores.output_id → agent_outputs.output_id`

### 2.5 feedback

Stores feedback provided by users about RCA results.

| Column | Type | Constraints | Description |
|---|---|---|---|
| feedback_id | UUID | PRIMARY KEY | Unique feedback identifier |
| user_id | UUID | FOREIGN KEY, NOT NULL | User providing feedback |
| output_id | UUID | FOREIGN KEY, NOT NULL | Agent output being evaluated |
| rating | INTEGER | | User rating |
| comments | TEXT | | User comments |
| is_correct | BOOLEAN | | Whether RCA was considered correct |
| created_at | TIMESTAMP | NOT NULL | Feedback creation time |

Foreign keys:

`feedback.user_id → users.user_id`

`feedback.output_id → agent_outputs.output_id`

## 3. Relationships

- One user can submit many incidents.
- One user can provide many feedback records.
- One incident can have multiple agent outputs.
- One agent output can have multiple confidence-score records.
- One agent output can receive multiple feedback records.

## 4. Normalization

The schema follows relational normalization principles:

- Each table represents a single logical entity.
- Each table has a primary key.
- Foreign keys establish relationships between entities.
- Repeated data is avoided.
- Agent outputs are separated from incidents.
- Confidence scores are separated from agent outputs.
- Feedback is stored independently from agent analysis.
